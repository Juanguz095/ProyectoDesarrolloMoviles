Fecha: 24 de octubre de 2026, UTC. Checkout `/home/juan/Downloads/ProyectoDesarrolloMoviles`, rama `main`. Comprobaciones locales sobre datos ficticios. **Las apps no se ejecutaron en emulador ni dispositivo**: esta evidencia distingue lo compilado y probado en JVM de lo que sigue sin validar.

## Entregables

| Tarea | Implementación |
| --- | --- |
| P4.1 | Agente Compose con consentimiento explícito, inscripción por código de un uso, credencial cifrada con Android Keystore (AES/GCM) y botón de evento simulado. |
| P4.2 | Centro de control Compose con login, listado de dispositivos y eventos, creación de códigos (solo admin) y consulta auditada por el servidor. |

Archivos principales:

- `apps/common/src/main/kotlin/com/auditlab/common/{Models,ApiClient,AgentCore,ControlCore}.kt`: cliente HTTP y lógica compartida, sin dependencias de Android.
- `apps/agent/src/main/java/com/auditlab/agent/{MainActivity,AgentSession,KeystoreCredentialStore}.kt` y `res/xml/network_security_config.xml`.
- `apps/control/src/main/java/com/auditlab/control/{MainActivity,ControlSession,KeystoreSessionStore}.kt` y `res/xml/network_security_config.xml`.
- Pruebas: `apps/common/src/test/kotlin/...` (23 unitarias) y `apps/common/src/smokeTest/kotlin/...` (3 de humo contra la API real).

## Decisiones técnicas

- **Módulo `apps/common` JVM puro** para que la lógica y el cliente HTTP se prueben sin emulador. `AuditApi` es una interfaz; `ApiClient` la implementa con `HttpURLConnection`, disponible en Android y JVM.
- **Credencial de dispositivo y sesión del centro cifradas con AES/GCM** y una clave no exportable de Android Keystore. SharedPreferences solo guarda IV + texto cifrado; no se implementa criptografía propia.
- **TLS obligatorio fuera de loopback**: `ApiClient` rechaza `http://` salvo `127.0.0.1`, `localhost` y `10.0.2.2`; el manifiesto desactiva tráfico en claro salvo esos dominios.
- **Revocación local primero**: `AgentCore.revokeLocally()` borra la credencial y cambia el estado antes de llamar al servidor, de modo que un fallo de red no deja la app enviando eventos. El resultado distingue `NOTIFIED` de `LOCAL_ONLY`.
- **Revocación remota**: al recibir `401 DEVICE_REVOKED`, el agente borra la credencial y muestra el estado revocado. Un `401 UNAUTHENTICATED` no se interpreta como revocación.
- **Renovación de sesión**: `ControlCore` refresca el access token una vez ante `401 UNAUTHENTICATED` y reintenta; si el refresh falla, cierra la sesión.
- **Código de inscripción**: se envía solo en la cabecera `X-Enrollment-Code`, nunca en la URL; el centro lo muestra una vez y no lo registra.
- **Roles**: el centro deshabilita crear códigos y revocar si el rol no es admin; el servidor vuelve a comprobarlo (403).

### Cobertura de las pruebas JVM

- **Cliente HTTP**: rechazo de HTTP fuera de loopback, cuerpo y cabeceras correctos en login/inscripción/eventos/revocación, credencial siempre en cabecera, `problem+json` convertido en `ApiException` con `code`/`correlationId`, error de red como `status = 0`, parseo de páginas de dispositivos y eventos.
- **Agente**: sin consentimiento no se inscribe ni llama a la API; el estado y la credencial usan el consentimiento canonicalizado del servidor; el evento usa identidad y consentimiento inscritos; sin inscripción no hay eventos; revocación remota y local bloquean envíos y borran la credencial; credencial guardada se recupera al iniciar.
- **Centro**: login y rol, auditor no crea códigos ni revoca, refresco único ante 401, cierre de sesión si el refresh falla, logout local aunque la API falle.
- **Humo real**: las mismas clases contra Ktor/PostgreSQL: código de un uso, inscripción, lote aceptado y reintento idempotente, dispositivo y evento visibles, revocación remota que devuelve `DEVICE_REVOKED`, y revocación local reflejada como `revoked` en el centro.

## Correcciones durante la verificación

- `appVersion` llega como `null` para dispositivos inscritos sin versión; el contrato lo permite (`string | null`). Se corrigió el modelo del cliente, no el servidor.
- `JSONObject.toMap()` existe en la biblioteca JVM pero **no en `org.json` de Android**; se sustituyó por una conversión propia para evitar un `NoSuchMethodError` en el dispositivo.
- `new URL(String)` está obsoleto en Java 20+; se usa `URI.create(...).toURL()` para compilar sin avisos manteniendo compatibilidad Android.

## Limitaciones

- **Sin ejecución en Android**: no hay `/dev/kvm` ni imagen de sistema instalada, y no se dispone de dispositivo físico. No se ejecutaron las pantallas Compose, Android Keystore, la política de red del manifiesto ni el recorrido manual de P4.1–P4.3. **No se declara el APK validado.**
- **La prueba de humo no sustituye al dispositivo**: usa el cliente y la lógica compartida, pero no Keystore, ni la UI, ni el tráfico real del emulador.
- **Sin HTTPS ni despliegue**: el servicio sigue en loopback; la guía TLS existe pero no se publicó.
- **Sin pruebas instrumentadas** de Compose; quedan para la fase de validación.
- **Sin persistencia de eventos pendientes** ni reintentos: eso corresponde a P5.
