## Diagnósticos y correcciones de entorno

1. Gradle no podía cargar servicios nativos con la caché del directorio personal. Se configuró `GRADLE_USER_HOME` dentro de `.tooling`.
2. SDK Manager fallaba al escribir `/home/agent/.android/cache`; el diagnóstico verbose mostró `NoSuchFileException`. Se usó `ANDROID_USER_HOME` escribible.
3. La primera compilación encontró Java sin capacidad `JAVA_COMPILER`; se instaló un JDK completo desde Oracle y se verificó su SHA-256 oficial.
4. Una prueba con variables Android antiguas/nuevas contradictorias produjo `AndroidLocationsException`. Se eliminó la variable legacy añadida en el helper; se mantiene una sola ruta Android moderna.
5. Lint detectó icono faltante y reglas de backup incompletas. Se añadieron iconos y exclusiones explícitas para cloud/device transfer en Android 12+, además de desactivar full backup para versiones anteriores.
6. Un intento de leer informes incrementales conservó un XML de una ejecución previa. No se usó como evidencia final: se forzó la regeneración con `--rerun-tasks` y se verificaron los resultados nuevos.
7. La prueba negativa de contraseña reveló que localhost dentro de la imagen PostgreSQL inicial aceptaba confianza por defecto. Se exigió `--auth-host=scram-sha-256` al inicializar el contenedor, se esperó una conexión TCP real y se repitieron los casos negativo y positivo. La prueba de conexión anterior no se considera evidencia de rechazo de contraseñas.

No se desactivaron TLS, checksums, firmas ni validaciones. La CA pública del proxy se añadió a un truststore local conservando las raíces del sistema. Persisten avisos de métricas Android por el directorio personal no escribible; los APKs, firmas y análisis de lint fueron comprobados independientemente.

## Conclusión y límites

**P0.2 y P2.1 verificadas:** herramientas reproducibles, conexión PostgreSQL y tres módulos base compilados. Las apps contienen pantallas informativas con monitoreo desactivado; no implementan todavía el flujo del producto. Ktor solo implementa salud de proceso, no conexión BD ni rutas de negocio. No se ejecutaron pruebas instrumentadas, instalación en equipos propios, producción HTTPS ni firma release. PostgreSQL de desarrollo no reemplaza el diseño de privilegios/migraciones de P2.3.

Se guardaron `install_script` y `start_skill` en el borrador del entorno con confirmación `saved`. Esto no aplica ni publica la configuración y no prueba restauración en una tarea nueva. Siguiente implementación: P2.2, contrato definitivo; después P2.3, migraciones.
