La validación no contacta servidores ilustrativos.

## Decisiones de interfaz

- Login/refresh/logout con sesiones revocables y refresh rotatorio; usuario de acceso separado de credencial de dispositivo.
- Código de inscripción devuelve una credencial una vez; consumo inválido/vencido/reutilizado usa `401 ENROLLMENT_CODE_INVALID`.
- Detalle de evento por dispositivo + ID; evita asumir que `eventId` es único globalmente.
- Eventos incluyen marca explícita de simulación; recepción asigna `receivedAt`. Entrada y salida tienen esquemas distintos.
- Cursores opacos ligados a actor/filtros y orden estable; filtros de exportación coinciden con historial y no hay truncado silencioso.
- Auditoría con actor/tipo, recurso, filtros, resultado, correlación y acciones de seguridad/recepción.
- Códigos de error distinguen credencial, rol, consentimiento, revocación, conflicto de ID y límite de exportación.

Resultado: **P2.2 verificada como contrato de desarrollo**. La cronología, los límites en bytes, autorización real, transacciones, firma de cursor, refresh y compatibilidad HTTP de las rutas nuevas requieren las pruebas de implementación de fase 3. No se declaran implementados por validarse sus esquemas. La API Python sigue correspondiendo a 0.1; no se cambió su comportamiento para aparentar cumplimiento del contrato nuevo.
