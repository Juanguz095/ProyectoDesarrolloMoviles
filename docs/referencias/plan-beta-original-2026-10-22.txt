# Plan de desarrollo — AuditLab

Proyecto académico · Desarrollo de Aplicaciones Móviles · Sesión 6

Vamos a organizar el desarrollo de AuditLab desde cero, siguiendo los 12 incrementos del PDF. El objetivo es que puedas construir la aplicación, comprender cómo funciona y demostrarle al profesor que cada etapa cumple sus requisitos.

Te propongo un cronograma de 10 días de trabajo, con sesiones aproximadas de 2 a 3 horas. Este tiempo es una estimación mía, no un plazo establecido por el documento.

## 1. Resultado final del proyecto

Al terminar, tendrás una aplicación Android en Kotlin que permite generar eventos ficticios de llamadas y mensajes, consultar su historial, almacenar información localmente, eliminar registros, revocar la aceptación y exportar datos a CSV.

La aplicación tendrá dos módulos principales:

AuditLab

Aplicación Android

app

Interfaz, SQLite y funciones Android

domain

Modelos, reglas, CSV y pruebas Kotlin

## 4. Herramientas y configuración

Según el contrato maestro incluido en el PDF, debes mantener esta configuración inicialmente:

| Componente                 | Versión           |
| -------------------------- | ----------------- |
| Android Studio             | IDE de desarrollo |
| Lenguaje                   | Kotlin            |
| Android Gradle Plugin      | 9.1.1             |
| Gradle                     | 9.3.1             |
| JDK                        | 17                |
| compileSdk / targetSdk     | 36                |
| minSdk                     | 26                |
| Kotlin JVM plugin (domain) | 2.2.10            |

El PDF advierte de una posible limitación de compatibilidad entre el plugin Kotlin JVM 2.2.10 y Gradle 9.3.1. Por eso, no deberías cambiar versiones automáticamente: primero verifica la compilación y documenta cualquier problema.

También te recomiendo crear un repositorio Git para conservar cada incremento aprobado.

## 6. Cómo verificar cada avance

El PDF establece que no debes continuar al siguiente incremento hasta revisar y aprobar el actual.

Para cada incremento conserva:

- El código y los archivos modificados.
- El `git diff` para revisar los cambios.
- El resultado real de compilación.
- Las pruebas automatizadas y manuales aplicables.
- Los errores y las correcciones realizadas.
- Una captura o informe que demuestre el funcionamiento.

En Windows, algunos comandos útiles serán:

```
.\gradlew.bat --version
.\gradlew.bat :domain:test
.\gradlew.bat :app:assembleDebug
```

Es importante distinguir entre una prueba propuesta y una prueba realmente ejecutada.

## 7. Qué debes hacer hoy: comenzar I01

Para el primer día, céntrate exclusivamente en preparar una base compilable.

Lista de preparación

0/6

Instalar o abrir Android Studio.

Comprobar que JDK 17 está disponible.

Crear la carpeta del proyecto AuditLab.

Cuando termines I01, tendrás un proyecto Android que abre y compila, aunque todavía no tenga los botones de simulación. Eso es exactamente lo esperado para esta primera etapa.

Mi recomendación es desarrollar AuditLab utilizando Android Studio y un asistente de IA, pero sin pedirle que implemente los 12 incrementos de golpe. El documento está diseñado para que construyas, revises y comprendas cada parte antes de avanzar.
